*كل خوارزمية ستتعلّمها هي جواب على السؤال نفسه: كم مرة يُنفَّذ هذا السطر؟ ليس "هل هذا سريع"، فذلك يتوقّف على حاسوبك، بل "كم خطوة"، وهذا لا يتوقّف عليه. هذا الجزء يبني تلك العادة الواحدة، لأن لا شيء آخر في السلسلة يقوم من دونها.*

أريد أن أبدأ من مكان صغير حقًا. ليس بتعريف، ولا بحرف يوناني، بل ببرنامج يجمع أعدادًا.

## ١. البرنامج الأول، والسؤال الأول

تُعطى قائمة أعداد ويُطلب منك مجموعها.

```python
def total(numbers):
    running = 0
    for n in numbers:
        running += n
    return running
```

والآن السؤال الوحيد المهم: **كم مرة يُنفَّذ السطر `running += n`؟**

مرة واحدة لكل عدد. إذا كانت القائمة تحتوي ١٠ أعداد فسيُنفَّذ ١٠ مرات. وإذا كانت تحتوي مليونًا فسيُنفَّذ مليون مرة. اكتب ذلك كقاعدة، وستكون قد قلت شيئًا صحيحًا عن هذا البرنامج على كل حاسوب وُجد يومًا:

```
  steps  =  n
```

حيث `n` هو عدد الأعداد. هذه هي الفكرة كلها. وكل ما تبقّى في هذه السلسلة هو هذه الفكرة مطبَّقة على برامج أصعب.

لاحظ ما *لم* نفعله. لم نقِس الزمن. قياس الزمن يخبرك عن حاسوبك، وعن حالة مركز البيانات، وعمّا إذا كان المتصفّح مفتوحًا. أما العدّ فيخبرك عن البرنامج.

## ٢. برنامج ثانٍ يبدو مثله وليس مثله

مهمّة مختلفة الآن. تُعطى قائمة أعداد، والسؤال: هل يوجد زوج مجموعه صفر؟

هذه هي المحاولة الأولى الصادقة، التي يكتبها الجميع:

```python
def has_zero_pair(numbers):
    for a in numbers:
        for b in numbers:
            if a is not b and a + b == 0:
                return True
    return False
```

كم مرة يُنفَّذ سطر المقارنة؟ لكل قيمة من قيم `a` وعددها `n`، تدور الحلقة الداخلية `n` مرة. إذن:

```
  steps  =  n × n  =  n²
```

البرنامجان يبدوان على الورق متساويين في التعقيد تقريبًا. وهما ليسا متساويين في التكلفة على الإطلاق. ضع أرقامًا:

| n | المجموع: n خطوة | الزوج: n² خطوة |
|---|---|---|
| ١٠ | ١٠ | ١٠٠ |
| ١٠٠٠ | ١٠٠٠ | ١٠٠٠٠٠٠ |
| ١٠٠٠٠٠ | ١٠٠٠٠٠ | ١٠٠٠٠٠٠٠٠٠٠ |
| ١٠٠٠٠٠٠ | ١٠٠٠٠٠٠ | ١٠٠٠٠٠٠٠٠٠٠٠٠ |

أعد قراءة السطر الأخير. مليون خطوة تمرّ في لحظة. أما *تريليون* خطوة، وبتقدير متفائل جدًا يبلغ مليار خطوة في الثانية، فتحتاج نحو سبع عشرة دقيقة. كودان يبدوان متشابهين، سبع عشرة دقيقة مقابل لا شيء.

هذه هي اللحظة التي تدفع فيها العادة ثمن نفسها، ولهذا نعدّ قبل أن نكتب.

## ٣. القاعدة التقريبية التي تنجّيك في مسابقة

العتاد الحديث ينفّذ تقريبًا بين $10^8$ و$10^9$ عملية بسيطة في الثانية. ومسائل المسابقات تُوضع عادة بحدّ زمني من ثانية أو ثانيتين. فالقاعدة العملية:

> ينبغي أن يبقى حلّك تحت مئة مليون خطوة.

اجمع ذلك مع حجم الدخل الذي تعطيه المسألة، وستكون المسألة قد أخبرتك بأي خوارزمية تريد. هذا الجدول هو أنفع ما في هذا المقال. ما زلت أستخدمه.

| إذا كان n حتى | يمكنك تحمّل | أي |
|---|---|---|
| ١٠ | $n!$ | تجربة كل ترتيب |
| ٢٠ | $2^n$ | تجربة كل مجموعة جزئية |
| ٥٠٠ | $n^3$ | ثلاث حلقات متداخلة |
| ٥٠٠٠ | $n^2$ | حلقتان متداخلتان |
| $10^6$ | $n \log n$ | ترتيب، أو كومة |
| $10^7$ | $n$ | مرور واحد |
| $10^{18}$ | $\log n$ | بحث ثنائي، أو رياضيات |

المسألة التي تقول "n حتى ٢٠٠٠٠٠" تخبرك بلغة واضحة أن $n^2$ لن ينجح، وأن عليك إيجاد شيء حول $n \log n$. هذه ليست إشارة مخفيّة في النص. هذه *هي* المسألة.

## ٤. أين تختبئ الخطوات

العدّ سهل حين تكون الحلقات مرئية. أما الأخطاء فتأتي من خطوات لم تكتبها.

**حلقة داخل نداء مكتبة.** هذا يبدو سطرًا واحدًا:

```python
if x in numbers:      # numbers قائمة
    ...
```

وهو ليس خطوة واحدة. بايثون يمشي في القائمة كلها باحثًا عن `x`، فتكون التكلفة حتى `n` خطوة. ضع ذلك داخل حلقة على القائمة نفسها وتكون قد كتبت $n^2$ دون أن تكتب حلقة متداخلة. استخدم `set` فيصير السطر نفسه خطوة واحدة تقريبًا:

```python
seen = set(numbers)   # n خطوة، مرة واحدة
if x in seen:         # خطوة واحدة تقريبًا، كل مرة
    ...
```

**وصل النصوص داخل حلقة.** في معظم اللغات لا يمكن تمديد نصّ في موضعه، فـ `s = s + c` ينسخ النصّ بأكمله. افعل ذلك `n` مرة ويصبح مجموع النسخ $1 + 2 + \dots + n$، أي $n(n+1)/2$، وهو $n^2$ متنكّرًا.

```python
# n² نسخًا في المجموع
s = ''
for c in chars:
    s = s + c

# n، لأن join ينسخ مرة واحدة
s = ''.join(chars)
```

**التقطيع.** في بايثون، `numbers[1:]` يبني قائمة جديدة. والدالة الاستدعائية التي تقطّع دخلها في كل نداء تعمل أكثر بكثير ممّا يوحي به شكل الاستدعاء.

العادة التي تكشف الثلاثة: لكل سطر داخل حلقتك، اسأل *هل هذا فعلًا خطوة واحدة*. إذا كان السطر يلمس مجموعة كاملة، فهو ليس خطوة واحدة.

## ٥. مثال محلول: أكبر مجموع لمقطع متّصل

مسألة حقيقية. تُعطى قائمة أعداد، وعليك إيجاد أكبر مجموع ممكن لمقطع **متّصل** منها. لأجل `[3, -2, 5, -1]` الجواب `6`، من `[3, -2, 5]`.

**النسخة الأولى: تجربة كل مقطع وجمعه.** حلقتان لاختيار البداية والنهاية، وثالثة للجمع.

```python
def best_v1(a):
    n = len(a)
    best = a[0]
    for i in range(n):
        for j in range(i, n):
            s = 0
            for k in range(i, j + 1):
                s += a[k]
            best = max(best, s)
    return best
```

ثلاث حلقات متداخلة: $n^3$. عند $n = 5000$ يصبح ذلك $1.25 \times 10^{11}$ خطوة. أبطأ من اللازم بكثير.

**النسخة الثانية: التوقّف عن إعادة الجمع.** الحلقة الثالثة هدرٌ خالص. عندما يتحرك `j` خطوة إلى اليمين، يحتاج المجموع عملية جمع واحدة، لا مرورًا جديدًا.

```python
def best_v2(a):
    best = a[0]
    for i in range(len(a)):
        s = 0
        for j in range(i, len(a)):
            s += a[j]
            best = max(best, s)
    return best
```

$n^2$. عند $n = 5000$ يصبح ذلك ٢٥ مليون خطوة، وهو مقبول. وعند $n = 10^6$ ليس كذلك.

**النسخة الثالثة: اسأل سؤالًا أفضل.** بدلًا من "ما أفضل مقطع"، اسأل "ما أفضل مقطع *ينتهي هنا*". امشِ من اليسار إلى اليمين، وفي كل موضع لديك خياران بالضبط: تمديد المقطع الذي كنت تبنيه، أو التخلّي عنه والبدء من جديد عند هذا العنصر.

```python
def best_v3(a):
    best = here = a[0]
    for x in a[1:]:
        here = max(x, here + x)     # تمديد، أو بداية جديدة
        best = max(best, here)
    return best
```

حلقة واحدة. $n$ خطوة. عند $n = 10^6$ يستغرق ذلك جزءًا من الألف من الثانية.

```
  a       3    -2     5    -1
          |     |     |     |
  here    3     1     6     5      extend or restart
  best    3     3     6     6      the running answer
```

تلك خوارزمية كادان، ولا أعرضها لتحفظها. أعرضها من أجل شكل الحكاية: $n^3 \to n^2 \to n$، وكل خطوة جاءت من ملاحظة عمل مكرّر ورفض تكراره. تصميم الخوارزميات *هو هذا*. وكل جزء تقريبًا في هذه السلسلة هو حالة أخرى منه.

## ٦. ما لا يقوله أحد في البداية

عدّ الخطوات يخبرك كيف *تنمو* التكلفة. وهو لا يقول شيئًا، عن قصد، عن الثابت الذي أمامها. برنامج ينفّذ $100n$ خطوة وآخر ينفّذ $2n$ كلاهما "$n$"، وأحدهما أبطأ خمسين مرة.

هذا ليس عيبًا، بل هو المقصود. النموّ هو الجزء الذي ينجو من تغيير الحاسوب؛ والثابت لا ينجو. لكن يتبع ذلك أمران صادقان:

١. في الأحجام الصغيرة، تفوز الخوارزمية "الأسوأ" غالبًا. ترتيب الإدراج يتغلّب على الترتيب السريع تحت اثني عشر عنصرًا تقريبًا، ولهذا تنتقل التطبيقات الحقيقية إليه في الأسفل.
٢. عندما يتساوى نموّ حلّين، لا يبقى إلا الثابت، وعندها *تقيس* فعلًا. الجزء العشرون من هذه السلسلة مخصّص بكامله للثوابت التي تأتي من الذاكرة لا من عدد الخطوات.

## ٧. التمرين الذي ينفع فعلًا

افعل هذا أسبوعًا وتثبت العادة. خُذ أي دالة كتبتها وأجب كتابةً عن ثلاثة أسئلة:

١. ما هو `n`؟ سمِّه. نصف الالتباس هنا سببه برنامج فيه حجمان مختلفان، كشبكة من `r` صفًا و`c` عمودًا، يُوصَف بحرف واحد.
٢. كم مرة يُنفَّذ السطر الأعمق، بدلالة `n`؟
٣. بالنظر إلى حجم الدخل الذي تسمح به المسألة، هل هذا تحت مئة مليون؟

إذا لم تستطع الإجابة عن السؤال الأول فأنت لم تفهم المسألة بعد. وهذا يحدث أكثر مما تحبّ، ومعرفته مبكرًا هي المنفعة كلها.

## باختصار

- عُدّ كم مرة يُنفَّذ السطر الأعمق. لا تقِس الزمن؛ الزمن يقيس حاسوبك، والعدّ يقيس برنامجك.
- يبدو $n$ و$n^2$ متساويين في البساطة على الورق. وعند مليون عنصر يكون أحدهما لحظيًا والآخر سبع عشرة دقيقة.
- الميزانية نحو مئة مليون خطوة في الثانية. وحجم الدخل في نصّ المسألة يخبرك بأي خوارزمية تُطلب.
- تختبئ الخطوات داخل أسطر تبدو بريئة: `in` على قائمة، ووصل النصوص في حلقة، والتقطيع. إذا لمس السطر مجموعة كاملة فهو ليس خطوة واحدة.
- الخوارزميات الأفضل تأتي دائمًا تقريبًا من ملاحظة عمل مكرّر ورفض تكراره. هذه هي الحيلة كلها، وبقية السلسلة تنويعات عليها.

في الجزء التالي: تسمية النموّ، ولماذا $\mathcal{O}(n)$ ادّعاء عن شكل منحنى لا عن سرعة.
