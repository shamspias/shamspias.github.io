*আপনি যত অ্যালগরিদম শিখবেন, সবই আসলে একই প্রশ্নের উত্তর: এই লাইনটা কতবার চলে? "এটা কি দ্রুত" নয়, কারণ সেটা আপনার ল্যাপটপের ওপর নির্ভর করে; বরং "কত ধাপ", কারণ সেটা নির্ভর করে না। এই পর্বে শুধু ওই একটা অভ্যাসই তৈরি করব, কারণ এটা ছাড়া সিরিজের বাকি কিছুই দাঁড়ায় না।*

আমি সত্যিই একেবারে ছোট জায়গা থেকে শুরু করতে চাই। কোনো সংজ্ঞা দিয়ে নয়, কোনো গ্রিক অক্ষর দিয়েও নয়। একটা প্রোগ্রাম দিয়ে, যেটা সংখ্যা যোগ করে।

## ১. প্রথম প্রোগ্রাম, আর প্রথম প্রশ্ন

আপনাকে কিছু সংখ্যার একটা তালিকা দেওয়া হলো, আর তাদের যোগফল চাওয়া হলো।

```python
def total(numbers):
    running = 0
    for n in numbers:
        running += n
    return running
```

এখন একমাত্র যে প্রশ্নটা গুরুত্বপূর্ণ: **`running += n` লাইনটা কতবার চলে?**

প্রতিটি সংখ্যার জন্য একবার। তালিকায় ১০টি সংখ্যা থাকলে ১০ বার। ১০ লাখ থাকলে ১০ লাখ বার। এটাকে একটা নিয়ম হিসেবে লিখে ফেলুন, আর তাতেই এমন কিছু বলা হয়ে গেল যা পৃথিবীর প্রতিটি কম্পিউটারে সত্য:

```
  ধাপ  =  n
```

যেখানে `n` হলো সংখ্যাগুলোর মোট পরিমাণ। এটাই পুরো ধারণা। এই সিরিজের বাকি সব কিছু হলো এই ধারণাটাই আরও কঠিন প্রোগ্রামে প্রয়োগ করা।

লক্ষ করুন আমরা কী *করিনি*। আমরা সময় মাপিনি। সময় মাপলে জানা যায় আপনার ল্যাপটপ সম্পর্কে, ডেটা সেন্টারের আবহাওয়া সম্পর্কে, আর ক্রোম খোলা ছিল কি না তা সম্পর্কে। গুনলে জানা যায় প্রোগ্রাম সম্পর্কে।

## ২. দ্বিতীয় প্রোগ্রাম, দেখতে একই, আসলে নয়

এবার অন্য কাজ। সংখ্যার একটা তালিকা দেওয়া হলো, প্রশ্ন: এমন কোনো জোড়া আছে কি যাদের যোগফল শূন্য?

সবাই প্রথমে যেটা লেখে, সেই সৎ চেষ্টাটা এখানে:

```python
def has_zero_pair(numbers):
    for a in numbers:
        for b in numbers:
            if a is not b and a + b == 0:
                return True
    return False
```

তুলনার লাইনটা কতবার চলে? `a`-এর প্রতিটি `n` মানের জন্য ভেতরের লুপ `n` বার চলে। তাহলে:

```
  ধাপ  =  n × n  =  n²
```

কাগজে দুটো প্রোগ্রাম প্রায় সমান জটিল দেখায়। কিন্তু খরচে তারা একেবারেই সমান নয়। সংখ্যা বসিয়ে দেখুন:

| n | যোগফল: n ধাপ | জোড়া: n² ধাপ |
|---|---|---|
| ১০ | ১০ | ১০০ |
| ১,০০০ | ১,০০০ | ১০,০০,০০০ |
| ১,০০,০০০ | ১,০০,০০০ | ১০,০০,০০,০০,০০০ |
| ১০,০০,০০০ | ১০,০০,০০০ | ১০,০০,০০,০০,০০,০০০ |

শেষ সারিটা আবার পড়ুন। দশ লাখ ধাপ চোখের পলকে হয়ে যায়। এক *লাখ কোটি* ধাপ, খুব আশাবাদী হিসাবে সেকেন্ডে একশো কোটি ধাপ ধরলেও, প্রায় সতেরো মিনিট। দেখতে একই কোড, একদিকে সতেরো মিনিট, অন্যদিকে কিছুই না।

এই মুহূর্তেই অভ্যাসটা নিজের দাম তুলে নেয়, আর এই কারণেই আমরা লেখার আগে গুনি।

## ৩. প্রতিযোগিতায় যে হিসাবটা কাজে লাগবে

আজকের হার্ডওয়্যার মোটামুটি সেকেন্ডে $10^8$ থেকে $10^9$ সাধারণ অপারেশন করে। প্রতিযোগিতার সমস্যায় সাধারণত এক বা দুই সেকেন্ড সময়সীমা থাকে। তাই কাজের নিয়ম:

> আপনার সমাধান দশ কোটির কমে ধাপ শেষ করা উচিত।

এর সঙ্গে সমস্যায় দেওয়া ইনপুটের আকার মিলিয়ে নিন, আর সমস্যাটাই আপনাকে বলে দেবে কোন অ্যালগরিদম সে চায়। এই টেবিলটাই এই লেখার সবচেয়ে কাজের জিনিস। আমি এখনো এটা ব্যবহার করি।

| n যদি সর্বোচ্চ হয় | আপনি করতে পারেন | মানে |
|---|---|---|
| ১০ | $n!$ | প্রতিটি ক্রম দেখা |
| ২০ | $2^n$ | প্রতিটি উপসেট দেখা |
| ৫০০ | $n^3$ | তিনটি নেস্টেড লুপ |
| ৫,০০০ | $n^2$ | দুটি নেস্টেড লুপ |
| $10^6$ | $n \log n$ | সাজানো, বা একটি হিপ |
| $10^7$ | $n$ | এক পাস |
| $10^{18}$ | $\log n$ | বাইনারি সার্চ, বা গণিত |

যে সমস্যায় লেখা থাকে "n সর্বোচ্চ ২,০০,০০০", সেটা সরল ভাষায় বলে দিচ্ছে যে $n^2$ কাজ করবে না, আর আপনাকে $n \log n$-এর আশপাশে কিছু খুঁজতে হবে। এটা সমস্যার ভেতরে লুকানো ইঙ্গিত নয়। এটাই *সমস্যার বক্তব্য*।

## ৪. ধাপগুলো কোথায় লুকায়

লুপ চোখে দেখা গেলে গোনা সহজ। ভুল হয় সেই ধাপগুলোতে যেগুলো আপনি লেখেননি।

**লাইব্রেরি কলের ভেতরে লুকানো লুপ।** এটা দেখতে এক লাইন:

```python
if x in numbers:      # numbers একটি list
    ...
```

এটা এক ধাপ নয়। পাইথন `x` খুঁজতে পুরো তালিকা হাঁটে, তাই এটা `n` পর্যন্ত ধাপ। একই তালিকার ওপর লুপের ভেতরে রাখলে নেস্টেড লুপ না লিখেই আপনি $n^2$ লিখে ফেললেন। `set` ব্যবহার করলে একই লাইন প্রায় এক ধাপ হয়ে যায়:

```python
seen = set(numbers)   # n ধাপ, একবার
if x in seen:         # প্রায় ১ ধাপ, প্রতিবার
    ...
```

**লুপের ভেতরে স্ট্রিং জোড়া দেওয়া।** বেশির ভাগ ভাষায় স্ট্রিং জায়গামতো বাড়ানো যায় না, তাই `s = s + c` পুরো স্ট্রিং কপি করে। `n` বার করলে কপির মোট খরচ $1 + 2 + \dots + n$, যা $n(n+1)/2$, অর্থাৎ ছদ্মবেশে $n^2$।

```python
# মোট n² কপি
s = ''
for c in chars:
    s = s + c

# n, কারণ join একবারই কপি করে
s = ''.join(chars)
```

**স্লাইসিং।** পাইথনে `numbers[1:]` নতুন একটা তালিকা বানায়। যে রিকার্সিভ ফাংশন প্রতিবার ইনপুট স্লাইস করে, সে রিকার্শনের চেহারা যা বলছে তার চেয়ে অনেক বেশি কাজ করছে।

তিনটিই ধরা পড়ে একটি অভ্যাসে: লুপের প্রতিটি লাইনের জন্য প্রশ্ন করুন, *এটা কি সত্যিই এক ধাপ*। লাইনটা যদি পুরো একটা কালেকশন ছোঁয়, তবে সেটা এক ধাপ নয়।

## ৫. হাতে-কলমে উদাহরণ: সবচেয়ে বড় ধারাবাহিক যোগফল

এবার একটা সত্যিকারের সমস্যা। কিছু সংখ্যা দেওয়া আছে, তাদের মধ্যে **পাশাপাশি** থাকা একটা অংশের সবচেয়ে বড় যোগফল বের করতে হবে। `[3, -2, 5, -1]`-এর উত্তর `6`, যা আসে `[3, -2, 5]` থেকে।

**সংস্করণ এক: প্রতিটি অংশ নিয়ে যোগ করা।** শুরু আর শেষ বাছতে দুটি লুপ, আর যোগ করতে তৃতীয়টি।

```python
def best_v1(a):
    n = len(a)
    best = a[0]
    for i in range(n):
        for j in range(i, n):
            s = 0
            for k in range(i, j + 1):
                s += a[k]
            best = max(best, s)
    return best
```

তিনটি নেস্টেড লুপ: $n^3$। $n = 5000$-এ সেটা $1.25 \times 10^{11}$ ধাপ। অনেক বেশি ধীর।

**সংস্করণ দুই: বারবার যোগ করা বন্ধ করা।** তৃতীয় লুপটা পুরোপুরি অপচয়। `j` এক ঘর ডানে সরলে যোগফলের জন্য একটি যোগই দরকার, নতুন করে হাঁটা নয়।

```python
def best_v2(a):
    best = a[0]
    for i in range(len(a)):
        s = 0
        for j in range(i, len(a)):
            s += a[j]
            best = max(best, s)
    return best
```

$n^2$। $n = 5000$-এ ২৫ লাখ ধাপ, যা ঠিক আছে। $n = 10^6$-এ নয়।

**সংস্করণ তিন: প্রশ্নটাই বদলে দেওয়া।** "সবচেয়ে ভালো অংশ কোনটা" জিজ্ঞেস না করে জিজ্ঞেস করুন "*এখানে শেষ হওয়া* সবচেয়ে ভালো অংশ কোনটা"। বাঁ থেকে ডানে হাঁটুন, আর প্রতিটি জায়গায় ঠিক দুটি পছন্দ আছে: আগের অংশটা বাড়িয়ে নেওয়া, বা সেটা ফেলে দিয়ে এখান থেকে নতুন শুরু করা।

```python
def best_v3(a):
    best = here = a[0]
    for x in a[1:]:
        here = max(x, here + x)     # বাড়ানো, নাকি নতুন শুরু
        best = max(best, here)
    return best
```

একটা লুপ। $n$ ধাপ। $n = 10^6$-এ এক মিলিসেকেন্ড।

```
  a       3    -2     5    -1
          |     |     |     |
  here    3     1     6     5      বাড়ানো বা নতুন শুরু
  best    3     3     6     6      চলতি উত্তর
```

এটাই কাদানের অ্যালগরিদম, আর আমি এটা দেখাচ্ছি মুখস্থ করার জন্য নয়। দেখাচ্ছি গল্পের আকারটার জন্য: $n^3 \to n^2 \to n$, আর প্রতিটি ধাপ এসেছে পুনরাবৃত্ত কাজ চোখে পড়া আর সেটা দুবার করতে অস্বীকার করা থেকে। অ্যালগরিদম ডিজাইন *এটাই*। এই সিরিজের প্রায় প্রতিটি পর্ব এরই আরেকটা রূপ।

## ৬. যেটা কেউ প্রথমে বলে না

ধাপ গোনা বলে দেয় খরচ কীভাবে *বাড়ে*। সামনের গুণিতক সংখ্যাটা নিয়ে সে ইচ্ছে করেই কিছু বলে না। $100n$ ধাপের একটা প্রোগ্রাম আর $2n$ ধাপের একটা, দুটোই "$n$", আর একটা অন্যটার চেয়ে পঞ্চাশ গুণ ধীর।

এটা ত্রুটি নয়, এটাই উদ্দেশ্য। বৃদ্ধির হারই নতুন ল্যাপটপে টিকে থাকে; গুণিতকটা টেকে না। তবে এর মানে দুটো সৎ কথা:

১. ছোট ইনপুটে "খারাপ" অ্যালগরিদম প্রায়ই জেতে। এক ডজনের কম উপাদানে ইনসার্শন সর্ট কুইকসর্টকে হারায়, আর এ কারণেই আসল সর্ট ইমপ্লিমেন্টেশন নিচের দিকে ইনসার্শন সর্টে চলে যায়।
২. দুটো সমাধানের বৃদ্ধির হার এক হলে গুণিতকই একমাত্র পার্থক্য, আর তখন আপনি সত্যিই *মেপে দেখেন*। এই সিরিজের ২০তম পর্ব পুরোটাই সেই গুণিতক নিয়ে, যেটা আসে মেমরি থেকে, ধাপের হিসাব থেকে নয়।

## ৭. যে অভ্যাস আসলে কাজে দেয়

এক সপ্তাহ এটা করলে অভ্যাসটা থেকে যাবে। নিজের লেখা যেকোনো ফাংশন নিন আর লিখে তিনটি প্রশ্নের উত্তর দিন:

১. `n` কী? নাম দিন। এখানে অর্ধেক বিভ্রান্তির কারণ হলো এমন প্রোগ্রাম যার ভেতরে দুটো আলাদা আকার আছে, যেমন `r` সারি আর `c` কলামের একটা গ্রিড, অথচ একটাই অক্ষর দিয়ে বর্ণনা করা হচ্ছে।
২. ভেতরের সবচেয়ে গভীর লাইনটা `n`-এর হিসাবে কতবার চলে?
৩. সমস্যা যে ইনপুট আকার দেয়, তাতে সেটা কি দশ কোটির কম?

প্রথম প্রশ্নের উত্তর দিতে না পারলে আপনি সমস্যাটা এখনো বোঝেননি। এটা যত ভাবেন তার চেয়ে বেশিবার ঘটে, আর তাড়াতাড়ি জানতে পারাটাই আসল লাভ।

## সংক্ষেপে

- ভেতরের সবচেয়ে গভীর লাইন কতবার চলে গুনুন। সময় মাপবেন না; সময় মাপে আপনার ল্যাপটপ, গোনা মাপে আপনার প্রোগ্রাম।
- কাগজে $n$ আর $n^2$ সমান সহজ দেখায়। দশ লাখ উপাদানে একটা চোখের পলকে হয়, অন্যটায় সতেরো মিনিট লাগে।
- সেকেন্ডে মোটামুটি দশ কোটি ধাপই বাজেট। সমস্যায় দেওয়া ইনপুটের আকার বলে দেয় কোন অ্যালগরিদম চাওয়া হচ্ছে।
- নিরীহ দেখতে লাইনের ভেতরে ধাপ লুকায়: list-এ `in`, লুপে স্ট্রিং জোড়া, স্লাইসিং। কোনো লাইন যদি পুরো কালেকশন ছোঁয়, সেটা এক ধাপ নয়।
- ভালো অ্যালগরিদম প্রায় সবসময় আসে পুনরাবৃত্ত কাজ চোখে পড়া আর সেটা আবার না করা থেকে। এটাই পুরো কৌশল, আর সিরিজের বাকিটা এরই বিভিন্ন রূপ।

পরের পর্ব: বৃদ্ধির হারকে নাম দেওয়া, আর কেন $\mathcal{O}(n)$ আসলে গতি নয়, বরং একটা বক্ররেখার আকৃতি নিয়ে দাবি।
